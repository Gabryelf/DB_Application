## 🎯 Что это за проект

Мы создаём базу данных для учебного заведения **«Цифровая Академия»**: ученики, учителя, предметы, группы, расписание, оценки и связанные сущности.

**Спринт 1** — каждый студент создаёт **одну таблицу** (SQL-скрипт для MySQL 8+) в своей персональной папке. База данных проектируется по **третьей нормальной форме (3НФ)**: без дублирования данных, все неключевые поля зависят только от первичного ключа, между таблицами — корректные внешние ключи.

## ✅ Требования к работе (обязательно)

### Технические
- **MySQL 8+**, движок **InnoDB**, кодировка **utf8mb4**.
- Файл: `database/scripts/entities/<table>/create_table.sql`.
- Таблица должна создаваться без ошибок (проверьте локально или в онлайн-редакторе MySQL).

### Именование (единые правила — чтобы все поля были предсказуемы)
| Что | Как называть | Пример |
|---|---|---|
| Таблица | `snake_case`, множественное число | `students`, `exam_results` |
| Первичный ключ | **всегда** `id` | `id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY` |
| Внешний ключ | `<сущность>_id` | `student_id`, `group_id` |
| Логические поля | `is_*`, `has_*` | `is_active`, `has_access` |
| Даты | `*_at` (момент) / `*_date` (день) | `created_at`, `birth_date` |
| Статусы | `status ENUM(...)` | `status ENUM('active','expelled')` |
| Деньги | `DECIMAL(10,2)` | `amount DECIMAL(10,2)` |

> Если поле ссылается на другую таблицу — оно **всегда** называется `<имя_таблицы_в_единственном_числе>_id`. Например, ссылка на `students` → `student_id`, на `groups` → `group_id`. Это позволяет **предугадать** имя поля в любой таблице.

### Первичные и внешние ключи
- **PRIMARY KEY** обязателен в каждой таблице.
- **FOREIGN KEY** — если ваша сущность ссылается на другую таблицу из [Схемы](https://github.com/TopCollegeTCF/DB_Application/wiki/Схема-сущностей).
- Все FK: `ON UPDATE CASCADE`. `ON DELETE` — по смыслу: `RESTRICT` для справочников, `CASCADE` для связок.
- Внешние ключи добавляйте **даже если таблица-родитель ещё не готова** — менеджер при проверке целостности увидит зависимости.

### Нормализация — 3НФ
База должна работать по **третьей нормальной форме**:
1. **1НФ** — атомарные значения, нет повторяющихся групп полей.
2. **2НФ** — все неключевые поля зависят от **полного** первичного ключа.
3. **3НФ** — нет транзитивных зависимостей (неключевые поля не зависят друг от друга).

На практике:
- Не храните вычисляемые значения (например, `full_name`, если есть `first_name` + `last_name`).
- Не дублируйте данные из других таблиц — используйте FK.
- Справочники (статусы, типы, категории) выносите в отдельные таблицы или `ENUM`.

### Комментарии в SQL
- `COMMENT='...'` у таблицы — обязательно.
- Комментарии к ключевым полям — приветствуются.

## 🤝 Как работать вместе

- **Заглядывайте в папки друг друга** — если ваша таблица ссылается на `students`, посмотрите, как её проектирует однокурсник.
- **Скооперируйтесь** через **Discussions** (раздел Q&A): уточняйте типы полей, названия FK, `ON DELETE`-политики.
- **Общая цель** — чтобы все 23 таблицы собрались в **целостную БД по 3НФ**, которая запустится без ошибок и будет готова к следующим спринтам (процедуры, триггеры).
